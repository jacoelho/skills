# Compare roles, families and transitions

## Levels
1. Element: label, perceptibility, state and affordance.
2. Pattern: fields, action groups, feedback and collections.
3. Surface: hierarchy, reading/grouping relationships and adaptation.
4. Family/application: stable grammar and justified local variation.
5. Journey: information, object and interaction continuity through changes.

Success at one level does not imply success at another.

## Coherence matrix

| --- | --- | --- | --- | --- | --- |

Compare the same operation and role, not every button with every other button. Include modal, sheet and panel instances. The same component name does not prove consistent actual rendering or behaviour; ancestry, context and state can change it.

Examples of meaningful findings: navigation renames the same destination only on settings; the same edit dialog acquires a different vocabulary when opened from detail; validation is inline on one form but hidden behind a footer in another; status is updated in detail but stale in the list.

Examples of acceptable variation: smaller overlay heading than page heading; lower-density reading view than task table; different destructive-action treatment; a narrow sheet preserving the desktop dialog's semantics. Require a reason, not uniformity for its own sake.

## Screenshot atlas
Group by application and journey, then label surface, state, caller, available space and revision. Do not mix unrelated websites as if they shared one design contract. Thumbnails support comparison; inspect originals for text, focus and clipping. Use same-scale crops for corresponding roles when measuring or comparing details.

## Alignment and spacing
Compare equivalent relationships using each surface's local origin, including shared modals from distinct callers. For requested annotated evidence or unresolved alignment/spacing questions, use [reference-line overlays](reference-line-overlays.md).

## Minimal transition evidence
For each relevant edge record precondition, input, observed next state, retained/changed data, focus/attention and feedback. Test return/back and cancellation as well as forward progress. Distinguish visible evidence from actual state/semantic/operation evidence.
