# Invoice download: a worked contract and restart

This is invented product data for learning and evaluation development. It does
not establish a policy for a real invoice system. The Python callable models a
download boundary; its checks do not exercise HTTP, storage, or a deployed
authorisation service.

## Request, question, and decision

Request: let an account download an invoice from the API or a previously issued
link. Link expiry and export formatting are outside this increment.

Distinguishing question: a link was issued while access was granted; access is
revoked before download. Should that link still return the invoice?

The example product owner chooses current access at download time. The governing
[access policy](policy.md) requires withholding data when access is denied or
cannot be established. The existing link implementation in [bad.py](bad.py)
returns data after revocation. This is an implementation defect under that
policy, not permission to rewrite the policy to fit the link.

The [contract](contract.md) records the settled local behaviour in EARS and references
the shared invariant. The [task record](task.md) keeps the formatting question,
implementation assignment, and restart information separate from the contract.

## Acceptance and execution

[expected.json](expected.json) owns the concrete acceptance values chosen for
this example. The probe reads these values independently of the implementation.
An illustrative Gherkin rendering of its revoked-link case is:

```gherkin
Scenario: Access revoked after a download link was issued
  Given an invoice link was issued while account access was granted
  And access is denied when the download is requested
  When the account downloads through that link
  Then the response status is 403
  And the response contains no invoice data
```

This scenario is proposed acceptance text, not an executed check or another
policy definition. Its rule is REQ-DOWNLOAD-002; its oracle is the example owner's
decision and access policy; its exercised boundary is the download callable.

From this directory, run:

```sh
python3 -B probe.py --implementation good
python3 -B probe.py --implementation bad
```

The good implementation must satisfy all six cases. The bad control must fail
the two link cases that withhold data. A probe accepting both implementations
would miss the promised boundary. Actual results and file identities belong in
[evidence.json](evidence.json), generated by the maintainer after running these
commands; prose and expected values alone are not execution evidence.

## Correction and fresh-context continuation

The correction in [good.py](good.py) applies the same current-access decision to
both paths. A new agent receives only `task.md` and its linked sources. It checks
their current state against the evidence identities before reusing a result.
If the access policy changes, it reopens affected decisions and refreshes the
probe evidence. An unrelated formatting question remains unresolved; it does
not block the settled access correction.

The example and its known wrong control are development data. Evaluation
variants should change the domain and conditions rather than reward recall of
these invoice values.
