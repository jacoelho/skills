# Canonical glossary

Maintain organisation-wide technical terminology here. The orchestrator passes the same frozen snapshot to every discovery, writer, reviewer, and editor agent that handles a document. When no glossary entry exists, preserve the source term exactly and propose a definition; do not improvise a canonical replacement.

Prefer repeating a canonical technical noun over replacing it with a stylistic synonym.

## Entry format

### Canonical term

- **Definition:** Exact meaning in this organisation or system.
- **Abbreviation:** Allowed abbreviation, or `none`.
- **Allowed aliases:** Only aliases that genuinely refer to the same thing.
- **Avoid:** Ambiguous, obsolete, promotional, or incorrect alternatives.
- **Usage notes:** Capitalisation, pluralisation, scope, or distinctions from nearby concepts.
- **Owner/source:** Person, team, standard, or document that defines the term.

## Example entry

### Payment Write API

- **Definition:** The API that accepts a new payment submission and records it durably before downstream processing.
- **Abbreviation:** PWA, after first expansion.
- **Allowed aliases:** none.
- **Avoid:** payment service, ingestion layer, writer, front end.
- **Usage notes:** Do not use this term for Gateway or Bridge responsibilities.
- **Owner/source:** Payments architecture.
