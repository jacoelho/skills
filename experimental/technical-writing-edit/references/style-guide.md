# Core style guide for precise technical documents

Read this core for every editing mode. Then read the selected mode reference from the same folder.

The selected document profile determines required content. This guide controls expression and presentation; it does not authorise new engineering reasoning.

## Precedence

Apply rules in this order:

1. Preserve factual and semantic correctness.
2. Preserve explicit task constraints and protected material.
3. Preserve the selected profile and intended reader task.
4. Preserve canonical glossary terms and normative language.
5. Apply this guide and the selected mode reference.
6. Apply non-binding author preference.

## Semantic boundary

The canonical claim kinds are `observation`, `report`, `inference`, `assumption`, `proposal`, `decision`, `requirement`, `forecast`, `risk`, `unknown`, and `action`.

Preserve each claim's kind. `Requirement` includes mandatory, prohibited, default, and permitted behaviour; express those subtypes with the correct normative word.

Do not add or alter:

- Facts, evidence, mechanisms, rationale, owners, requirements, decisions, metrics, benefits, or conclusions.
- Numbers, units, dates, identifiers, component names, chronology, or risk severity.
- Negation, conditions, exceptions, scope, ownership, causality, confidence, or evidence attachment.
- `must`, `must not`, `should`, `should not`, `may`, `will`, `expect`, or `propose`.

When an edit requires interpretation or missing information, return a substantive finding instead.

## Shared style

- Use a calm, candid, technically neutral voice.
- Prefer concrete actors, verbs, mechanisms, conditions, and consequences.
- Keep evidence adjacent to the claim it supports.
- Use one canonical term for one concept; do not vary technical nouns for style.
- Keep uncertainty, drawbacks, dissent, exceptions, and open questions visible.
- Remove throat-clearing, sales language, rhetorical pressure, emojis, decorative separators, forced groups of three, and artificial conclusions.
- Use lists for genuinely parallel items and tables for stable comparisons.
- Prefer informative sentence-case headings.
- Preserve the strongest fair representation of material competing views, explanations, or alternatives required by the profile.

## Completion check

Before returning edited text, confirm that:

1. No information was removed except genuine duplication.
2. Every material qualification and exception remains attached to its claim.
3. No proposal became a decision, forecast became a guarantee, or report became an observation.
4. No reasoning gap was replaced by a fluent transition.
5. A sceptical reader can still reconstruct the argument and its limits.
